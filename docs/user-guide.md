## เข้าสู่ระบบ / สมัครสมาชิก

หน้า `/login` มี 2 โหมดสลับกันได้: **Sign in** (เข้าสู่ระบบด้วยอีเมล+รหัสผ่าน) และ **Sign up** (สมัครใหม่ — กรอกชื่อ, อีเมล, รหัสผ่านอย่างน้อย 8 ตัวอักษร) บัญชีที่สมัครเองผ่านหน้านี้จะได้ role **member** เสมอ (เลือก role เองตอนสมัครไม่ได้ ไม่ว่าจะกรอกอะไรก็ตาม) ถ้าต้องการ role อื่นต้องให้ admin เปลี่ยนให้ทีหลังผ่านหน้า [Users](#users-admin-เท่านั้น) ถ้ามี session อยู่แล้วเข้าหน้านี้จะถูกพาไป Dashboard ทันที

## บทบาทผู้ใช้ (Roles)

ทุกคนต้อง sign in ก่อนถึงจะเข้าแอปได้ (ไม่มีหน้าไหนเปิดสาธารณะ) บทบาทมี 3 แบบ กำหนดโดย admin เท่านั้น (ผู้ใช้ตั้ง role ให้ตัวเองไม่ได้แม้ตอนสมัคร):

| ความสามารถ | Admin | Manager | Member |
| --- | --- | --- | --- |
| ดูโปรเจกต์/issue ทั้งหมด | ✅ | ✅ | ✅ |
| สร้างโปรเจกต์ใหม่ | ✅ | ✅ | ❌ |
| สร้าง issue ในโปรเจกต์ | ✅ | ✅ | ✅ |
| แก้ไข/ลบ issue | ✅ ทุก issue | ✅ ใน โปรเจกต์ที่ตัวเองเป็นเจ้าของ | ✅ เฉพาะ issue ที่ตัวเองเป็นคนสร้างหรือถูก assign |
| assign งานให้คนอื่น | ✅ ใครก็ได้ | ✅ ใครก็ได้ | เฉพาะตัวเองหรือคนแผนกเดียวกัน |
| Log Work / แก้ไขเวลาของตัวเอง | ✅ | ✅ | ✅ |
| แก้ไข/ลบเวลาที่คนอื่น log ไว้ | ✅ | ❌ | ❌ |
| ดูรายงานชั่วโมงทำงาน | ✅ ทุกคน | ✅ ทีมในโปรเจกต์ที่ตัวเองเป็นเจ้าของ + ของตัวเอง | ✅ เฉพาะของตัวเอง |
| จัดการ user/แผนก (`/users`) | ✅ | ❌ | ❌ |

บัญชีทดสอบหลัง `bun run db:seed` (รหัสผ่านทั้งหมด `password123`) ดูได้ใน [`README.md`](../README.md#เริ่มใช้งาน)

## Dashboard

หน้าแรกที่เจอหลัง sign in (`/`) — สรุปภาพรวมงานของตัวเอง ประกอบด้วย:

- **Stat cards** — จำนวน issue ที่สร้าง, จำนวนที่ถูก assign, ชั่วโมงทำงานสัปดาห์นี้
- **Recent Time Entries** — เวลาที่ตัวเอง log ไปล่าสุด 20 รายการ ข้ามทุกโปรเจกต์ (อยู่บนสุดของหน้าให้เห็นทันทีไม่ต้องเลื่อนหา)
- **Issue Status** — สัดส่วนสถานะของ issue ที่ถูก assign ให้ตัวเอง
- **Work Hour Analysis** — กราฟชั่วโมงทำงานย้อนหลัง เลือกช่วงได้ (5D / 2W / 1M / 6M / 1Y)
- **Time Tracker** — จับเวลาทำงานแบบ real-time: เลือกโปรเจกต์ (+issue ถ้ามี) แล้วกด Start จะนับเวลาไปเรื่อยๆ จนกด Stop ถึงจะบันทึกเป็น time entry จริง (คนละกลไกกับ "Log Work" ที่กรอกเวลาย้อนหลังในหน้าโปรเจกต์)
- **My Issues** — issue ที่ถูก assign ให้ตัวเอง
- **Today** — ปฏิทินนัดหมาย (ยังเป็น placeholder ข้อมูลตัวอย่าง ยังไม่เชื่อม calendar จริง)

## Projects

### รายการโปรเจกต์ (`/projects`)

แสดงโปรเจกต์ที่ยัง active ทั้งหมด พร้อมจำนวน issue ที่ยังไม่เสร็จและชั่วโมงที่ log สะสม Admin/Manager สร้างโปรเจกต์ใหม่ได้จากปุ่มมุมบนขวา (ต้องตั้ง key ย่อ เช่น `WEB`, `APP` — ใช้ขึ้นต้นเลข issue เช่น `WEB-101`)

โปรเจกต์ที่ archive แล้วจะไม่โผล่ในหน้านี้ แต่ยังเห็นได้จาก sidebar กลุ่ม **Archived** (คลิก "Active Projects" เพื่อขยาย/ยุบดูรายชื่อ)

### หน้ารายละเอียดโปรเจกต์ (`/projects/$id`)

ตาราง issue ทั้งหมดของโปรเจกต์นั้น แต่ละแถวมี:

- Status / Priority — เปลี่ยนได้ตรงๆ จาก dropdown ถ้ามีสิทธิ์
- Assignee, Labels, Due date
- **Logged** — คลิกตัวเลขเวลาเพื่อเปิด work log ของ issue นั้น (ดูหัวข้อ [Time Tracking](#time-tracking))
- **Log** / **Edit** / delete — ปุ่มจัดการ issue ตามสิทธิ์ของแต่ละคน

ปุ่ม **New issue** มุมบนขวาไว้สร้าง issue ใหม่ในโปรเจกต์นี้

### โปรเจกต์ที่ archive แล้ว

เปิดดูได้ตามปกติ (badge "Archived" จะขึ้นข้างชื่อ) แต่เป็น **read-only**: สร้าง issue ใหม่ไม่ได้, แก้ไข/ลบ issue เดิมไม่ได้, log เวลาใหม่ไม่ได้

> ⚠️ **ตอนนี้ยังไม่มีปุ่มไหนในหน้าจอให้ archive หรือ unarchive โปรเจกต์เลย** ระบบฝั่ง server รองรับ (`status: 'active' | 'archived'`) และหน้า detail พร้อมแสดงผล read-only ถูกต้องถ้าโปรเจกต์อยู่ในสถานะนั้น แต่ยังไม่มี UI ให้ผู้ใช้กดเปลี่ยนสถานะเองได้ — ตอนนี้ทำได้แค่แก้ตรงฐานข้อมูลเท่านั้น ถือเป็นงานที่ยังต้องต่อเติม

## Issues

แต่ละ issue มีเลขรันต่อโปรเจกต์ (เช่น `WEB-101`, `WEB-102`) และมีฟิลด์:

- Title, Description
- Status: Backlog → Todo → In Progress → Review → Done
- Priority: Low / Medium / High
- Assignee (ใครจะเป็นคนทำ) และ Reporter (ใครสร้าง — กำหนดอัตโนมัติเป็นคนที่สร้าง)
- Due date (เลือกผ่าน date picker แบบปฏิทิน ไม่ใช่พิมพ์เอง)
- Labels (คั่นด้วยจุลภาค เช่น `frontend, design`)

สร้าง/แก้ไขผ่าน drawer ด้านขวา (ปุ่ม **New issue** / **Edit**) ลบผ่านปุ่ม **delete** ท้ายแถว (เห็นเฉพาะคนมีสิทธิ์)

## Time Tracking

มี 2 วิธีลงเวลา:

### 1. Time Tracker (จับเวลาสด)

อยู่ในหน้า Dashboard — เลือกโปรเจกต์ (และ issue ถ้าอยากผูก) กด **Start** จะนับเวลาเดินหน้าไปเรื่อยๆ จนกว่าจะกด **Stop** ถึงตอนนั้นระบบถึงคำนวณระยะเวลาจริงแล้วบันทึกเป็น time entry ให้เอง เหมาะกับตอนกำลังนั่งทำงานอยู่จริงๆ

### 2. Time Tracking modal (log ย้อนหลัง แบบ Jira)

กดปุ่ม **Log** ที่แถว issue ในหน้าโปรเจกต์ จะเปิด modal "Time tracking" มีฟิลด์:

- **Time spent** — เวลาที่ใช้ไป พิมพ์แบบย่อได้ เช่น `1h 45m`, `1:45`, `90` (นาทีเปล่า), หรือรวมหน่วยใหญ่ เช่น `2w 4d 6h 45m` (w=สัปดาห์, d=วัน, h=ชั่วโมง, m=นาที)
- **Time remaining** — เวลาคงเหลือโดยประมาณของ issue นั้น จะ auto ลดตาม Time spent ที่พิมพ์ให้อัตโนมัติ (ถ้า issue เคยตั้งเวลาคงเหลือไว้ก่อน) แต่แก้เองได้ตลอด — ค่าที่กดบันทึกจะถูกใช้เป็นเวลาคงเหลือใหม่ของ issue เสมอ
- แถบ progress bar ด้านบนแสดง "logged vs remaining" ของ issue นั้นแบบสดๆ ตามที่พิมพ์
- **Date started** + **Time** — วันที่/เวลาที่เริ่มทำงานจริง (ไม่ใช่วันที่กดบันทึก)
- **Work description** — โน้ตว่าทำอะไรไปบ้างในช่วงเวลานั้น (ไม่บังคับ)

### ดู/แก้ไข work log ของ issue

คลิกตัวเลขเวลาที่คอลัมน์ **Logged** ในตาราง issue จะเปิด drawer "Work log" แสดงทุกรายการเวลาที่เคย log ไว้ในissue นั้น (ทุกคน) มี filter **All / Mine** ให้กรองดูเฉพาะของตัวเอง และปุ่ม **Edit** / **delete** ต่อรายการ (เห็นเฉพาะเจ้าของรายการหรือ admin)

## Reports

`/reports` — ตารางสรุปชั่วโมงทำงานต่อคนต่อโปรเจกต์ เลือกช่วงเวลาได้เหมือน Dashboard (5D/2W/1M/6M/1Y) ขอบเขตข้อมูลที่เห็นเป็นไปตามสิทธิ์ (ดูตาราง [บทบาทผู้ใช้](#บทบาทผู้ใช้-roles)) กดปุ่ม **Export CSV** มุมบนขวาเพื่อดาวน์โหลดตารางที่กำลังดูอยู่เป็นไฟล์ CSV

## Search (⌘K)

กด `⌘K` (Mac) หรือ `Ctrl+K` (Windows/Linux) จากหน้าไหนก็ได้ในแอป หรือกดปุ่ม "Search..." มุมบนขวา จะเปิดกล่องค้นหาแบบ command palette:

- พิมพ์ชื่อหรือ key โปรเจกต์ (เช่น `WEB`, `Website`) เพื่อกระโดดไปหน้าโปรเจกต์นั้น
- พิมพ์ชื่อหรือ key issue (เช่น `WEB-102`, `design system`) เพื่อกระโดดไปหน้าโปรเจกต์ของ issue นั้น
- หรือเลือกจากกลุ่ม **Pages** เพื่อไปหน้า Dashboard / Projects / Reports / Users / Settings ตรงๆ

## Theme

ไอคอน ☀️/🌙 มุมบนขวาของทุกหน้า กดแล้วเลือกได้ 3 แบบ: **Light**, **Dark**, **System** (ตาม OS) ค่าที่เลือกจำไว้ในเครื่อง (localStorage) เปิดแอปครั้งหน้าจะเป็นธีมเดิมทันทีไม่กะพริบ ถ้าเลือก System แล้ว OS สลับธีมระหว่างใช้งาน แอปจะตามให้อัตโนมัติ

## Notifications

ไอคอนกระดิ่งมุมบนขวา — **ตอนนี้ยังเป็น placeholder** ยังไม่มีระบบแจ้งเตือนจริง (ไม่มีการแจ้งเตือนงาน assign ใหม่ หรือใกล้ due date) กดแล้วจะเห็นข้อความ "ยังไม่มีการแจ้งเตือน" ตรงๆ ไม่มีตัวเลขปลอมมาหลอก

## Settings

`/settings` — ดูโปรไฟล์ตัวเอง (ชื่อ, อีเมล, บทบาท, แผนก, วันที่เข้าร่วม) หน้านี้เป็น read-only สำหรับตอนนี้ (แก้ข้อมูลส่วนตัวเองยังทำไม่ได้ — ถ้าจะเปลี่ยนแผนก/role ต้องให้ admin แก้ผ่านหน้า Users)

## Users (admin เท่านั้น)

`/users` — เห็นเฉพาะ admin (คนอื่นเข้ามาจะเจอ "Forbidden") ใช้:

- สร้างบัญชีผู้ใช้ใหม่ พร้อมกำหนด role และแผนก
- สร้างแผนกใหม่
- แก้ไข role/แผนกของผู้ใช้ที่มีอยู่แล้ว

## Sidebar และเมนูบัญชี

Sidebar ด้านซ้ายมีลิงก์ไปทุกหน้า (Dashboard, Reports, Active/Archived Projects, Settings, และ Users ถ้าเป็น admin) กดไอคอน `⬜` ในหัว header เพื่อยุบ/ขยาย sidebar ให้เหลือแค่ไอคอน

มุมล่างซ้ายของ sidebar เป็นชื่อ+อีเมลของตัวเอง กดแล้วเปิดเมนู:

- **Profile** — ลิงก์ไปหน้า Settings ของตัวเอง
- **Log out** — ออกจากระบบ กลับไปหน้า login

## ข้อจำกัดที่รู้อยู่แล้ว

- **ยังไม่มี UI สำหรับแก้ไขหรือ archive/unarchive โปรเจกต์เลย** — สร้างโปรเจกต์ใหม่ได้อย่างเดียว จะแก้ชื่อ/description หรือเปลี่ยนสถานะ active↔archived ต้องแก้ตรงฐานข้อมูล (ระบบฝั่ง server และหน้า detail รองรับสถานะ archived ไว้แล้ว รอแค่ปุ่มกดจริง)
- **Notifications** เป็น placeholder เฉยๆ ยังไม่มีแจ้งเตือนจริง
- **Today (Meetings/Events/Focus)** ในหน้า Dashboard เป็นข้อมูลตัวอย่าง ยังไม่เชื่อม calendar จริง
- **Settings** แก้ไขโปรไฟล์ตัวเองเองไม่ได้ ต้องให้ admin แก้แทน
- Search (⌘K) ค้นแค่ project/issue ยังไม่ครอบคลุมผู้ใช้หรือ time entry
